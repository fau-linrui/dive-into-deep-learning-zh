10.7. 机器翻译的序列到序列学习¶

在所谓的序列到序列问题（如机器翻译， 见 10.5节）中， 输入和输出都由长度可变、未对齐的序列组成， 此时我们通常依赖编码器-解码器架构 （10.6节）。 本节中， 我们将展示编码器-解码器架构 在机器翻译任务中的应用 (Cho et al., 2014, Sutskever et al., 2014)， 其中编码器和解码器 都实现为 RNN。

这里，编码器 RNN 将变长序列作为输入， 并将其变换为形状固定的隐藏状态。 稍后在 11节 中， 我们将介绍注意力机制， 它让我们无需把整个输入 压缩成单个固定长度的表示 就能访问编码后的输入。

然后，为了一次一个词元地 生成输出序列， 由单独 RNN 组成的解码器模型 将根据输入序列 和输出中前面的词元， 预测每个相继的目标词元。 训练时，解码器通常 以官方“真实标签”（ground truth）中 前面的词元为条件。 然而在测试时，我们希望 解码器的每个输出都以已经预测出的词元为条件。 请注意，如果忽略编码器， 序列到序列架构中的解码器 与普通的语言模型行为完全一样。 图10.7.1 展示了 如何用两个 RNN 进行机器翻译中的序列到序列学习。

在 图10.7.1 中， 特殊的“<eos>”词元 标记序列的结束。 一旦生成该词元， 我们的模型就可以停止预测。 在 RNN 解码器的初始时间步， 有两个需要特别注意的特殊设计决定： 第一，我们在每个输入的开头 放置一个特殊的序列开始“<bos>”词元。 第二，我们可以把 编码器的最终隐藏状态 在每个解码时间步都送入解码器 (Cho et al., 2014)。 在其他一些设计中， 例如 Sutskever et al. (2014) 的设计， RNN 编码器的最终隐藏状态 只用于在第一个解码步 初始化解码器的隐藏状态。

10.7.1. 教师强制¶

在输入序列上运行编码器 相对直接， 而处理解码器的输入和输出 则需要更加小心。 最常见的做法有时称为教师强制（teacher forcing）。 这里，原始的目标序列（词元标签） 被作为输入送入解码器。 更具体地说， 特殊的序列开始词元 和原始目标序列（除去最后一个词元） 连结成解码器的输入， 而解码器输出（用于训练的标签）则是 原始目标序列平移一个词元后的结果：“<bos>”、“Ils”、“regardent”、“.”\(\rightarrow\)“Ils”、“regardent”、“.”、“<eos>”（图10.7.1）。

我们在 10.5.3节 中的实现已经为教师强制准备好了训练数据， 其中为自监督学习而平移词元的做法， 与 9.3节 中 语言模型的训练相似。 另一种替代做法是 把上一时间步预测出的词元 作为解码器当前的输入。

下面，我们将更详细地解释 图10.7.1 所描绘的设计。 我们将使用 10.5节 中介绍的 英法数据集来训练该模型进行机器翻译。

10.7.2. 编码器¶

回想一下，编码器将长度可变的输入序列 变换为形状固定的上下文变量（context variable）\(\mathbf{c}\)（见 图10.7.1）。

考虑单个序列样例（批量大小为 1）。 假设输入序列为\(x_1, \ldots, x_T\)， 其中\(x_t\)是第\(t^{\textrm{th}}\)个词元。 在时间步\(t\)，RNN 把 输入特征向量\(\mathbf{x}_t\)（对应\(x_t\)） 和来自上一时间步的隐藏状态\(\mathbf{h} _{t-1}\) 变换为当前隐藏状态\(\mathbf{h}_t\)。 我们可以用函数\(f\)来表示 RNN 循环层的变换：

(10.7.1)¶\[\mathbf{h}_t = f(\mathbf{x}_t, \mathbf{h}_{t-1}).\]

一般而言，编码器通过一个自定义函数\(q\) 把所有时间步的隐藏状态 变换为上下文变量：

(10.7.2)¶\[\mathbf{c} = q(\mathbf{h}_1, \ldots, \mathbf{h}_T).\]

例如，在 图10.7.1 中， 上下文变量就是隐藏状态\(\mathbf{h}_T\)， 它对应编码器 RNN 在处理完输入序列的 最后一个词元之后的表示。

在这个例子中，我们使用了单向 RNN 来设计编码器， 其中隐藏状态只依赖于 该隐藏状态所在时间步及之前的输入子序列。 我们也可以使用双向 RNN 来构造编码器。 在这种情况下，一个隐藏状态依赖于 该时间步之前和之后的子序列 （包括当前时间步的输入）， 从而编码了整个序列的信息。

现在让我们实现 RNN 编码器。 请注意，我们使用嵌入层 来获得输入序列中每个词元的特征向量。 嵌入层的权重是一个矩阵， 其行数对应于 输入词表的大小（vocab_size）， 列数对应于 特征向量的维数（embed_size）。 对于任意输入词元索引\(i\)， 嵌入层取权重矩阵的第\(i^{\textrm{th}}\)行 （从 0 开始计数） 来返回其特征向量。 这里我们用多层 GRU 实现编码器。

def init_seq2seq(module):  #@save
    """Initialize weights for sequence-to-sequence learning."""
    if type(module) == nn.Linear:
         nn.init.xavier_uniform_(module.weight)
    if type(module) == nn.GRU:

            if "weight" in param:

10.7.3. 解码器¶

给定目标输出序列\(y_1, y_2, \ldots, y_{T'}\)， 对每个时间步\(t'\) （我们用\(t^\prime\)来区别于输入序列的时间步）， 解码器为第\(y_{t'+1}\)步可能出现的每个词元 赋予一个预测概率， 其条件为目标序列中前面的词元 \(y_1, \ldots, y_{t'}\) 以及上下文变量 \(\mathbf{c}\)，即\(P(y_{t'+1} \mid y_1, \ldots, y_{t'}, \mathbf{c})\)。

为了预测目标序列中后续的词元\(t^\prime+1\)， RNN 解码器把上一步的目标词元\(y_{t^\prime}\)、 来自上一时间步的 RNN 隐藏状态\(\mathbf{s}_{t^\prime-1}\) 以及上下文变量\(\mathbf{c}\)作为输入， 并把它们变换为当前时间步的 隐藏状态\(\mathbf{s}_{t^\prime}\)。 我们可以用函数\(g\)来表示 解码器隐藏层的变换：

(10.7.3)¶\[\mathbf{s}_{t^\prime} = g(y_{t^\prime-1}, \mathbf{c}, \mathbf{s}_{t^\prime-1}).\]

在得到解码器的隐藏状态之后， 我们可以使用输出层和 softmax 运算， 计算出关于后续输出词元\({t^\prime+1}\)的预测分布 \(p(y_{t^{\prime}+1} \mid y_1, \ldots, y_{t^\prime}, \mathbf{c})\)。

遵循 图10.7.1， 在如下实现解码器时， 我们直接使用编码器 最终时间步的隐藏状态 来初始化解码器的隐藏状态。 这要求 RNN 编码器和 RNN 解码器 具有相同的层数和隐藏单元数。 为了进一步纳入编码后的输入序列信息， 上下文变量在所有时间步 都与解码器输入连结。 为了预测输出词元的概率分布， 我们使用一个全连接层 来变换 RNN 解码器 最后一层的隐藏状态。

class Seq2SeqDecoder(d2l.Decoder):
    """The RNN decoder for sequence to sequence learning."""
    def __init__(self, vocab_size, embed_size, num_hiddens, num_layers,
                 dropout=0):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_size)
        self.rnn = d2l.GRU(embed_size+num_hiddens, num_hiddens,
                           num_layers, dropout)
        self.dense = nn.LazyLinear(vocab_size)
        self.apply(init_seq2seq)

    def init_state(self, enc_all_outputs, *args):
        return enc_all_outputs

    def forward(self, X, state):
        # X shape: (batch_size, num_steps)
        # embs shape: (num_steps, batch_size, embed_size)
        embs = self.embedding(X.t().type(torch.int32))
        enc_output, hidden_state = state
        # context shape: (batch_size, num_hiddens)
        context = enc_output[-1]
        # Broadcast context to (num_steps, batch_size, num_hiddens)
        context = context.repeat(embs.shape[0], 1, 1)
        # Concat at the feature dimension
        embs_and_context = torch.cat((embs, context), -1)
        outputs, hidden_state = self.rnn(embs_and_context, hidden_state)
        outputs = self.dense(outputs).swapaxes(0, 1)
        # outputs shape: (batch_size, num_steps, vocab_size)
        # hidden_state shape: (num_layers, batch_size, num_hiddens)
        return outputs, [enc_output, hidden_state]

        return enc_all_outputs

        # outputs shape: (batch_size, num_steps, vocab_size)
        # hidden_state shape: (num_layers, batch_size, num_hiddens)
        return outputs, [enc_output, hidden_state]

10.7.5. 带掩码的损失函数¶

在每个时间步，解码器 预测输出词元的概率分布。 与语言建模一样， 我们可以应用 softmax 得到该分布， 并计算交叉熵损失用于优化。 回想 10.5节 中的内容： 特殊的填充词元 被追加到序列末尾， 因此长度不一的序列 可以高效地加载到 形状相同的小批量中。 然而，填充词元的预测 应当从损失计算中排除。 为此，我们可以 用零值掩码无关项， 这样任何无关预测 与零相乘都等于零。

pytorchmxnetjaxtensorflow
@d2l.add_to_class(Seq2Seq)
def loss(self, Y_hat, Y):
    l = super(Seq2Seq, self).loss(Y_hat, Y, averaged=False)
    mask = (Y.reshape(-1) != self.tgt_pad).type(torch.float32)
    return (l * mask).sum() / mask.sum()

    return (l * mask).sum() / mask.sum()

@partial(jax.jit, static_argnums=(0, 5))
def loss(self, params, X, Y, state, averaged=False):
    Y_hat = state.apply_fn({'params': params}, *X,
                           rngs={'dropout': state.dropout_rng})
    Y_hat = Y_hat.reshape((-1, Y_hat.shape[-1]))
    Y = Y.reshape((-1,))
    fn = optax.softmax_cross_entropy_with_integer_labels
    l = fn(Y_hat, Y)
    mask = (Y.reshape(-1) != self.tgt_pad).astype(jnp.float32)
    return (l * mask).sum() / mask.sum(), {}

@d2l.add_to_class(Seq2Seq)
def loss(self, Y_hat, Y):
    l = super(Seq2Seq, self).loss(Y_hat, Y, averaged=False)
    mask = tf.cast(tf.reshape(Y, -1) != self.tgt_pad, tf.float32)
    return tf.reduce_sum(l * mask) / tf.reduce_sum(mask)

10.7.7. 预测¶

为了逐步预测输出序列， 上一时间步预测出的词元 会作为输入送入解码器。 一种简单的策略是： 在每一步预测时，选取解码器 赋予概率最高的那个词元。 与训练时一样，在初始时间步， 序列开始（“<bos>”）词元 被送入解码器。 这一预测过程 如 图10.7.3 所示。 当预测出序列结束（“<eos>”）词元时， 输出序列的预测就完成了。

下一节中，我们将介绍 基于束搜索的 更为精细的策略 （10.8节）。

def predict_step(self, params, batch, num_steps,
                 save_attention_weights=False):
    src, tgt, src_valid_len, _ = batch
    enc_all_outputs, inter_enc_vars = self.encoder.apply(
        {'params': params['encoder']}, src, src_valid_len, training=False,
        mutable='intermediates')
    # Save encoder attention weights if inter_enc_vars containing encoder
    # attention weights is not empty. (to be covered later)
    enc_attention_weights = []
    if bool(inter_enc_vars) and save_attention_weights:
        # Encoder Attention Weights saved in the intermediates collection
        enc_attention_weights = inter_enc_vars[
            'intermediates']['enc_attention_weights'][0]

    dec_state = self.decoder.init_state(enc_all_outputs, src_valid_len)
    outputs, attention_weights = [jnp.expand_dims(tgt[:,0], 1), ], []
    for _ in range(num_steps):
        (Y, dec_state), inter_dec_vars = self.decoder.apply(
            {'params': params['decoder']}, outputs[-1], dec_state,
            training=False, mutable='intermediates')
        outputs.append(Y.argmax(2))
        # Save attention weights (to be covered later)
        if save_attention_weights:
            # Decoder Attention Weights saved in the intermediates collection
            dec_attention_weights = inter_dec_vars[
                'intermediates']['dec_attention_weights'][0]
            attention_weights.append(dec_attention_weights)
    return jnp.concatenate(outputs[1:], 1), (attention_weights,
                                        enc_attention_weights)

10.7.8. 预测序列的评估¶

我们可以通过将预测序列与 目标序列（真实标签）进行比较 来评估它。 但是，衡量两个序列之间相似性的 合适指标究竟是什么呢？

双语评估替补（Bilingual Evaluation Understudy，BLEU） 最初是为评估机器翻译结果而提出的 (Papineni et al., 2002)， 但已被广泛用于衡量 不同应用中输出序列的质量。 原则上，对于预测序列中的任意\(n\)元语法（9.3.1.1节）， BLEU 评估该\(n\)元语法是否 出现在目标序列中。

用\(p_n\)表示\(n\)元语法的查准率， 其定义为预测序列与目标序列中 匹配的\(n\)元语法数量， 与预测序列中\(n\)元语法数量之比。 举例来说，给定目标序列\(A\)、\(B\)、\(C\)、\(D\)、\(E\)、\(F\)， 以及预测序列\(A\)、\(B\)、\(B\)、\(C\)、\(D\)， 我们有\(p_1 = 4/5\)、\(p_2 = 3/4\)、\(p_3 = 1/3\)和\(p_4 = 0\)。 现在令\(\textrm{len}_{\textrm{label}}\)和\(\textrm{len}_{\textrm{pred}}\) 分别表示目标序列 和预测序列中的词元数。 那么，BLEU 定义为

(10.7.4)¶\[\exp\left(\min\left(0, 1 - \frac{\textrm{len}_{\textrm{label}}}{\textrm{len}_{\textrm{pred}}}\right)\right) \prod_{n=1}^k p_n^{1/2^n},\]

其中\(k\)是用于匹配的最长\(n\)元语法。

根据 (10.7.4) 中 BLEU 的定义， 只要预测序列与目标序列相同，BLEU 就为 1。 此外， 由于匹配较长的\(n\)元语法更困难， 当较长的\(n\)元语法具有高查准率时， BLEU 会赋予更大的权重。 具体来说，当\(p_n\)固定时， \(p_n^{1/2^n}\)随着\(n\)的增大而增大（原论文使用的是\(p_n^{1/n}\)）。 此外， 由于 预测较短的序列 往往会得到较高的\(p_n\)值， (10.7.4) 中乘积项之前的系数 会惩罚较短的预测序列。 例如，当\(k=2\)时， 给定目标序列\(A\)、\(B\)、\(C\)、\(D\)、\(E\)、\(F\)以及预测序列\(A\)、\(B\)， 尽管\(p_1 = p_2 = 1\)，惩罚因子\(\exp(1-6/2) \approx 0.14\)仍会降低 BLEU。

我们如下实现 BLEU 指标。

def bleu(pred_seq, label_seq, k):  #@save
    """Compute the BLEU."""
    pred_tokens, label_tokens = pred_seq.split(' '), label_seq.split(' ')
    len_pred, len_label = len(pred_tokens), len(label_tokens)
    score = math.exp(min(0, 1 - len_label / len_pred))
    for n in range(1, min(k, len_pred) + 1):
        num_matches, label_subs = 0, collections.defaultdict(int)
        for i in range(len_label - n + 1):
            label_subs[' '.join(label_tokens[i: i + n])] += 1
        for i in range(len_pred - n + 1):
            if label_subs[' '.join(pred_tokens[i: i + n])] > 0:
                num_matches += 1
                label_subs[' '.join(pred_tokens[i: i + n])] -= 1
        score *= math.pow(num_matches / (len_pred - n + 1), math.pow(0.5, n))
    return score

10.7.9. 小结¶

遵循编码器-解码器架构的设计，我们可以使用两个 RNN 来设计序列到序列学习的模型。 在编码器-解码器的训练中，教师强制方法把原始输出序列（而非预测结果）送入解码器。 在实现编码器和解码器时，我们可以使用多层 RNN。 我们可以使用掩码过滤掉无关计算，例如在计算损失时。 对于输出序列的评估，BLEU 是一种流行的指标，它在预测序列与目标序列之间匹配\(n\)元语法。
