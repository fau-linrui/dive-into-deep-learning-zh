2.5. 自动微分¶

回想一下 2.4节 中的内容： 计算导数是训练深度网络时 将要使用的所有优化算法中的关键步骤。 虽然这些计算本身很直接， 但手工推导可能既繁琐又容易出错， 而且随着我们的模型变得越来越复杂， 这些问题只会不断加剧。

幸运的是，所有现代深度学习框架 都通过提供自动微分 （automatic differentiation， 常简写为autograd） 替我们承担了这项工作。 当我们让数据依次通过每一个函数时， 框架会构建一张计算图（computational graph）， 记录每个值如何依赖于其他值。 为了计算导数， 自动微分沿这张图 反向遍历并应用链式法则。 以这种方式应用链式法则的 计算算法称为反向传播（backpropagation）。

虽然autograd库在过去十年里 已成为热门的关注点， 但它们有着悠久的历史。 事实上，关于autograd的最早文献 可以追溯到半个多世纪以前 (Wengert, 1964)。 现代反向传播背后的核心思想 源自1980年的一篇博士论文 (Speelpenning, 1980)， 并在20世纪80年代后期得到进一步发展 (Griewank, 1989)。 虽然反向传播已成为计算梯度 的默认方法，但它并不是唯一的选择。 例如，Julia编程语言采用 前向传播 (Revels et al., 2016)。 在探索各种方法之前， 让我们先掌握autograd包。

pytorchmxnetjaxtensorflow
import torch

from mxnet import autograd, np, npx

npx.set_np()

from jax import numpy as jnp

import tensorflow as tf

2.5.1. 一个简单的函数¶

假设我们感兴趣的是 对函数 \(y = 2\mathbf{x}^{\top}\mathbf{x}\) 关于列向量\(\mathbf{x}\)求导。 首先，我们给x赋一个初始值。

pytorchmxnetjaxtensorflow
x = torch.arange(4.0)
x

在计算\(y\)关于\(\mathbf{x}\) 的梯度之前， 我们需要一个地方来存储它。 一般来说，我们避免每次求导 都分配新内存， 因为深度学习需要对同一组参数 连续计算导数很多很多次， 否则我们可能会面临内存耗尽的风险。 请注意，标量值函数 关于向量\(\mathbf{x}\)的梯度 是向量值的， 其形状与\(\mathbf{x}\)相同。

# Can also create x = torch.arange(4.0, requires_grad=True)
x.requires_grad_(True)
x.grad  # The gradient is None by default

x = np.arange(4.0)
x

# We allocate memory for a tensor's gradient by invoking `attach_grad`
x.attach_grad()
# After we calculate a gradient taken with respect to `x`, we will be able to
# access it via the `grad` attribute, whose values are initialized with 0s

x = tf.Variable(x)

2.5.2. 非标量变量的反向传播¶

当y是向量时， y关于向量x的导数 最自然的表示 是一个称为雅可比矩阵（Jacobian）的矩阵， 它包含y的每个分量 关于x的每个分量的偏导数。 同样，对于更高阶的y和x， 求导的结果可能是更高阶的张量。

虽然雅可比矩阵确实会出现在某些 高级机器学习技术中， 但更常见的是，我们希望把 y的每个分量关于整个向量x的梯度 加起来， 得到一个与x形状相同的向量。 例如，我们常常有一个向量， 它表示在一批训练样例中 为每个样例分别计算的损失函数值。 这里，我们只想把为每个样例 分别计算的梯度加起来。

pytorchmxnetjaxtensorflow

由于不同的深度学习框架 对非标量张量梯度 的解释各不相同， PyTorch采取了一些措施来避免混淆。 对非标量调用backward会引发错误， 除非我们告诉PyTorch如何把该对象降维为标量。 更形式化地说，我们需要提供某个向量\(\mathbf{v}\)， 使得backward计算的是 \(\mathbf{v}^\top \partial_{\mathbf{x}} \mathbf{y}\)， 而不是\(\partial_{\mathbf{x}} \mathbf{y}\)。 接下来的这部分可能令人困惑， 但出于后面将会清楚的原因， 这个参数（表示\(\mathbf{v}\)）被命名为gradient。 更详细的描述参见Yang Zhang的 Medium文章。

x.grad.zero_()
y = x * x
y.backward(gradient=torch.ones(len(y)))  # Faster: y.sum().backward()
x.grad

MXNet通过以下方式处理这个问题：在计算梯度之前， 先通过求和把所有张量降维为标量。 换句话说，它返回的不是 雅可比矩阵\(\partial_{\mathbf{x}} \mathbf{y}\)， 而是和函数的梯度 \(\partial_{\mathbf{x}} \sum_i y_i\)。

with autograd.record():
    y = x * x
y.backward()
x.grad  # Equals the gradient of y = sum(x * x)

y = lambda x: x * x
# grad is only defined for scalar output functions
grad(lambda x: y(x).sum())(x)

默认情况下，TensorFlow返回和函数的梯度。 换句话说，它返回的不是 雅可比矩阵\(\partial_{\mathbf{x}} \mathbf{y}\)， 而是和函数的梯度 \(\partial_{\mathbf{x}} \sum_i y_i\)。

with tf.GradientTape() as t:
    y = x * x
t.gradient(y, x)  # Same as y = tf.reduce_sum(x * x)

2.5.3. 分离计算¶

有时，我们希望把某些计算 移到记录的计算图之外。 例如，假设我们利用输入 创建了一些辅助的中间项， 而我们不想为这些项计算梯度。 在这种情况下，我们需要把 相应的计算图从最终结果中分离（detach）出来。 下面的玩具示例可以让这一点更清楚： 假设有z = x * y和y = x * x， 但我们想关注x对z的直接影响， 而不是经由y传递的影响。 在这种情况下，我们可以创建一个新变量u， 它与y取值相同， 但它的来源（即它是如何被创建的） 已经被抹去了。 因此u在图中没有祖先， 梯度也不会通过u流向x。 例如，对z = x * u求梯度 会得到结果u， （而不是你可能预期的3 * x * x， 因为z = x * x * x）。

pytorchmxnetjaxtensorflow
x.grad.zero_()
y = x * x
u = y.detach()
z = u * x

z.sum().backward()
x.grad == u

with autograd.record():
    y = x * x
    u = y.detach()
    z = u * x
z.backward()
x.grad == u

import jax

y = lambda x: x * x
# jax.lax primitives are Python wrappers around XLA operations
u = jax.lax.stop_gradient(y(x))
z = lambda x: u * x

grad(lambda x: z(x).sum())(x) == y(x)

# Set persistent=True to preserve the compute graph.
# This lets us run t.gradient more than once
with tf.GradientTape(persistent=True) as t:
    y = x * x
    u = tf.stop_gradient(y)
    z = u * x

x_grad = t.gradient(z, x)
x_grad == u

请注意，虽然这一过程 把y的祖先从通向z的图中分离了出去， 但通向y的计算图 仍然保留，因此我们仍然可以计算 y关于x的梯度。

pytorchmxnetjaxtensorflow
x.grad.zero_()
y.sum().backward()
x.grad == 2 * x

y.backward()
x.grad == 2 * x

grad(lambda x: y(x).sum())(x) == 2 * x

t.gradient(y, x) == 2 * x

2.5.4. 梯度和Python控制流¶

到目前为止，我们回顾的情形都是： 从输入到输出的路径 可以通过z = x * x * x之类的函数明确定义。 编程为我们计算结果的方式 提供了大得多的自由度。 例如，我们可以让结果依赖于辅助变量， 或者根据中间结果来决定选择。 使用自动微分的一个好处是： 即使要为 某个必须穿过由Python控制流构成的迷宫的函数 构建计算图 （例如条件语句、循环和任意函数调用）， 我们仍然可以计算结果变量的梯度。 为了说明这一点，考虑下面的代码片段， 其中while循环的迭代次数 和if语句的判断 都取决于输入a的值。

pytorchmxnetjaxtensorflow
def f(a):
    b = a * 2
    while b.norm() < 1000:
        b = b * 2
    if b.sum() > 0:
        c = b
    else:
        c = 100 * b
    return c

def f(a):
    b = a * 2
    while np.linalg.norm(b) < 1000:
        b = b * 2
    if b.sum() > 0:
        c = b
    else:
        c = 100 * b
    return c

def f(a):
    b = a * 2
    while jnp.linalg.norm(b) < 1000:
        b = b * 2
    if b.sum() > 0:
        c = b
    else:
        c = 100 * b
    return c

def f(a):
    b = a * 2
    while tf.norm(b) < 1000:
        b = b * 2
    if tf.reduce_sum(b) > 0:
        c = b
    else:
        c = 100 * b
    return c

下面，我们调用这个函数， 并传入一个随机值作为输入。 由于输入是一个随机变量， 我们不知道 计算图会呈现什么形式。 然而，每当我们在特定输入上 执行f(a)时，就会实例化 一张具体的计算图， 随后就可以运行backward。

pytorchmxnetjaxtensorflow
a = torch.randn(size=(), requires_grad=True)
d = f(a)
d.backward()

a = np.random.normal()
a.attach_grad()
with autograd.record():
    d = f(a)
d.backward()

from jax import random

a = random.normal(random.PRNGKey(1), ())
d = f(a)
d_grad = grad(f)(a)

a = tf.Variable(tf.random.normal(shape=()))
with tf.GradientTape() as t:
    d = f(a)
d_grad = t.gradient(d, a)
d_grad

尽管为了演示目的， 我们的函数f有些刻意构造， 但它对输入的依赖关系相当简单： 它是a的一个线性函数， 只是缩放系数是分段定义的。 因此，f(a) / a是一个各分量 均为常数的向量；而且， f(a) / a必须与 f(a)关于a的梯度一致。

pytorchmxnetjaxtensorflow
a.grad == d / a

a.grad == d / a

d_grad == d / a

d_grad == d / a

动态控制流在深度学习中非常常见。 例如，在处理文本时，计算图 取决于输入的长度。 在这些情况下，自动微分 对统计建模变得至关重要， 因为无法先验地计算梯度。

2.5.5. 讨论¶

现在你已经领略了自动微分的能力。 既能自动又能高效地 计算导数的库的发展， 极大地提升了深度学习实践者的生产力， 把他们解放出来，从而能够专注于 不那么琐碎的任务。 此外，autograd让我们能够设计庞大的模型， 对这些模型而言，用纸笔进行梯度计算 将耗时过多而不可行。 有趣的是，虽然我们用autograd来优化模型 （从统计意义上说）， 但autograd库自身的优化 （从计算意义上说） 却是一个内容丰富的课题， 对框架设计者至关重要。 在这里，来自编译器和图处理领域的工具 被用来以最便捷、 最节省内存的方式计算结果。

目前，请试着记住这些基础要点：(i) 为那些我们希望对其求导的变量附加梯度；(ii) 记录目标值的计算过程；(iii) 执行反向传播函数；(iv) 访问得到的梯度。
