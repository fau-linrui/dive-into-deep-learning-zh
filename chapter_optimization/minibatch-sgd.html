12.5. 小批量随机梯度下降¶

到目前为止，在基于梯度的学习方法中，我们遇到了两个极端：12.3节 使用整个数据集来计算梯度并更新参数，每次遍历一趟。相反，12.4节 每次处理一个训练样例来取得进展。 两者各有其缺点。 当数据非常相似时，梯度下降并不是特别数据高效。 随机梯度下降并不是特别计算高效，因为 CPU 和 GPU 无法发挥向量化的全部威力。 这表明两者之间可能存在某种折中方案， 事实上，这正是我们迄今为止在讨论的示例中一直在使用的方案。

12.5.1. 向量化与缓存¶

使用小批量的核心原因是计算效率。当考虑并行化到多个 GPU 和多个服务器时，这一点最容易理解。在这种情况下，我们需要向每个 GPU 至少发送一张图像。如果每台服务器有 8 个 GPU、共有 16 台服务器，那么我们就已经得到不小于 128 的小批量大小。

对于单个 GPU 甚至 CPU，情况要微妙一些。这些设备具有多种类型的内存，通常还有多种类型的计算单元，以及它们之间不同的带宽约束。 例如，CPU 有少量寄存器，然后还有 L1、L2，有时甚至还有 L3 缓存（后者在不同处理器核心之间共享）。 这些缓存的容量和延迟依次递增（同时带宽依次递减）。 可以说，处理器能够执行的操作远多于主存接口所能提供的操作。

首先，一个 2GHz、16 核且支持 AVX-512 向量化的 CPU 每秒最多可以处理\(2 \cdot 10^9 \cdot 16 \cdot 32 = 10^{12}\)字节。GPU 的能力很容易超过这个数字 100 倍。另一方面，一台中端服务器处理器的带宽可能不会比 100 GB/s 高多少，即不到满足处理器所需带宽的十分之一。更糟糕的是，并非所有内存访问都是等价的：内存接口通常是 64 位宽或更宽（例如在 GPU 上可达 384 位），因此读取单个字节要付出宽得多的访问代价。

其次，首次访问存在显著的开销，而顺序访问则相对便宜（这通常称为突发读取）。还有更多需要考虑的因素，例如当我们有多个插槽、小芯片（chiplet）以及其他结构时的缓存。 关于更深入的讨论，见这篇维基百科文章。

缓解这些约束的方法是使用层级化的 CPU 缓存，这些缓存实际上足够快，能够为处理器提供数据。这就是深度学习中批处理背后的那个驱动力。为简单起见，考虑矩阵-矩阵乘法，例如\(\mathbf{A} = \mathbf{B}\mathbf{C}\)。计算\(\mathbf{A}\)有若干种选择。例如，我们可以尝试以下方式：

  1. 我们可以计算\(\mathbf{A}_{ij} = \mathbf{B}_{i,:} \mathbf{C}_{:,j}\)，即通过点积按元素计算它。

  2. 我们可以计算\(\mathbf{A}_{:,j} = \mathbf{B} \mathbf{C}_{:,j}\)，即一次计算一列。同样，我们可以一次计算\(\mathbf{A}\)的一行\(\mathbf{A}_{i,:}\)。

  3. 我们可以简单地计算\(\mathbf{A} = \mathbf{B} \mathbf{C}\)。

  4. 我们可以把\(\mathbf{B}\)和\(\mathbf{C}\)分解为较小的块矩阵，一次计算\(\mathbf{A}\)的一个块。

如果我们采用第一种选择，那么每次想要计算元素\(\mathbf{A}_{ij}\)时，都需要把一行和一个列向量复制到 CPU 中。更糟糕的是，由于矩阵元素是顺序排列的，因此当我们从内存读取数据时，对于两个向量中的一个，我们不得不访问许多不相邻的位置。第二种选择要有利得多。在第二种选择中，我们能够把列向量\(\mathbf{C}_{:,j}\)保存在 CPU 缓存中，同时不断遍历\(\mathbf{B}\)。这将内存带宽需求减半，访问速度也相应更快。当然，选项 3 是最理想的。不幸的是，大多数矩阵可能无法完全放入缓存（毕竟这正是我们讨论的问题）。然而，选项 4 提供了一种实用的替代方案：我们可以把矩阵的块移入缓存，并在本地进行乘法运算。优化的库会为我们处理好这些。让我们看看这些操作在实际中的效率如何。

除了计算效率之外，Python 和深度学习框架本身引入的开销也相当可观。回想一下，每次执行一条命令时，Python 解释器都会向 MXNet 引擎发送一条命令，后者需要将其插入计算图并在调度期间处理它。这种开销可能相当有害。简言之，强烈建议尽可能使用向量化（以及矩阵）。

12.5.2. 小批量¶

过去，我们理所当然地认为应当读取小批量数据而不是单个观测来更新参数。现在我们对这种做法给出简要的理由。处理单个观测需要我们执行许多单次矩阵-向量（甚至向量-向量）乘法，这相当昂贵，并且会为底层深度学习框架带来显著开销。这既适用于将网络应用于数据（通常称为推理）时的求值，也适用于计算梯度以更新参数时。也就是说，只要执行\(\mathbf{w} \leftarrow \mathbf{w} - \eta_t \mathbf{g}_t\)，就适用这一点，其中

(12.5.1)¶\[\mathbf{g}_t = \partial_{\mathbf{w}} f(\mathbf{x}_{t}, \mathbf{w})\]

我们可以通过一次对一个小批量的观测执行该操作来提高其计算效率。也就是说，我们把单个观测上的梯度\(\mathbf{g}_t\)替换为小批量上的梯度

(12.5.2)¶\[\mathbf{g}_t = \partial_{\mathbf{w}} \frac{1}{|\mathcal{B}_t|} \sum_{i \in \mathcal{B}_t} f(\mathbf{x}_{i}, \mathbf{w})\]

让我们看看这对\(\mathbf{g}_t\)的统计性质有什么影响：由于\(\mathbf{x}_t\)以及小批量\(\mathcal{B}_t\)的所有元素都是从训练集中随机均匀抽取的，梯度的期望保持不变。另一方面，方差显著减小。由于小批量梯度由\(b \stackrel{\textrm{def}}{=} |\mathcal{B}_t|\)个被平均的独立梯度组成，其标准差减小为原来的\(b^{-\frac{1}{2}}\)倍。这本身是件好事，因为它意味着更新与完整梯度的方向更可靠地对齐。

天真地看，这似乎表明选择较大的小批量\(\mathcal{B}_t\)在任何情况下都是可取的。唉，在某个点之后，与计算代价的线性增长相比，标准差的额外减小微乎其微。在实践中，我们选择的小批量要足够大，以提供良好的计算效率，同时仍然能放入 GPU 的内存。为了说明这种节省，让我们看一段代码。在这段代码中，我们执行相同的矩阵-矩阵乘法，但这次将其分成每次 64 列的“小批量”。

12.5.4. 从零开始实现¶

回想一下 3.4节 中的小批量随机梯度下降实现。下面我们提供一个稍微更通用的实现。为方便起见，它与本章后面介绍的其他优化算法具有相同的调用签名。具体来说，我们添加状态输入states，并把超参数放入字典hyperparams。此外，我们将在训练函数中对每个小批量样例的损失取平均，因此优化算法中的梯度不需要再除以批量大小。

def sgd(params, states, hyperparams):
    for p in params:
        p.data.sub_(hyperparams['lr'] * p.grad)
        p.grad.data.zero_()

def sgd(params, states, hyperparams):
    for p in params:
        p[:] -= hyperparams['lr'] * p.grad

def sgd(params, grads, states, hyperparams):
    for param, grad in zip(params, grads):
        param.assign_sub(hyperparams['lr']*grad)

#@save
def train_ch11(trainer_fn, states, hyperparams, data_iter,
               feature_dim, num_epochs=2):
    # Initialization
    w = torch.normal(mean=0.0, std=0.01, size=(feature_dim, 1),
                     requires_grad=True)
    b = torch.zeros((1), requires_grad=True)
    net, loss = lambda X: d2l.linreg(X, w, b), d2l.squared_loss
    # Train
    animator = d2l.Animator(xlabel='epoch', ylabel='loss',
                            xlim=[0, num_epochs], ylim=[0.22, 0.35])
    n, timer = 0, d2l.Timer()
    for _ in range(num_epochs):
        for X, y in data_iter:
            l = loss(net(X), y).mean()
            l.backward()
            trainer_fn([w, b], states, hyperparams)
            n += X.shape[0]
            if n % 200 == 0:
                timer.stop()
                animator.add(n/X.shape[0]/len(data_iter),
                             (d2l.evaluate_loss(net, data_iter, loss),))
                timer.start()
    print(f'loss: {animator.Y[0][-1]:.3f}, {timer.sum()/num_epochs:.3f} sec/epoch')
    return timer.cumsum(), animator.Y[0]

#@save
def train_ch11(trainer_fn, states, hyperparams, data_iter,
               feature_dim, num_epochs=2):
    # Initialization
    w = tf.Variable(tf.random.normal(shape=(feature_dim, 1),
                                   mean=0, stddev=0.01),trainable=True)
    b = tf.Variable(tf.zeros(1), trainable=True)

    # Train
    net, loss = lambda X: d2l.linreg(X, w, b), d2l.squared_loss
    animator = d2l.Animator(xlabel='epoch', ylabel='loss',
                            xlim=[0, num_epochs], ylim=[0.22, 0.35])
    n, timer = 0, d2l.Timer()

    for _ in range(num_epochs):
        for X, y in data_iter:
          with tf.GradientTape() as g:
            l = tf.math.reduce_mean(loss(net(X), y))

          dw, db = g.gradient(l, [w, b])
          trainer_fn([w, b], [dw, db], states, hyperparams)
          n += X.shape[0]
          if n % 200 == 0:
              timer.stop()
              p = n/X.shape[0]
              q = p/tf.data.experimental.cardinality(data_iter).numpy()
              r = (d2l.evaluate_loss(net, data_iter, loss),)
              animator.add(q, r)
              timer.start()
    print(f'loss: {animator.Y[0][-1]:.3f}, {timer.sum()/num_epochs:.3f} sec/epoch')
    return timer.cumsum(), animator.Y[0]

在 Gluon 中，我们可以使用Trainer类来调用优化算法。它被用来实现一个通用的训练函数。我们将在本章中自始至终使用它。

#@save
def train_concise_ch11(trainer_fn, hyperparams, data_iter, num_epochs=4):
    # Initialization
    net = nn.Sequential(nn.Linear(5, 1))
    def init_weights(module):
        if type(module) == nn.Linear:
            torch.nn.init.normal_(module.weight, std=0.01)
    net.apply(init_weights)

    optimizer = trainer_fn(net.parameters(), **hyperparams)
    loss = nn.MSELoss(reduction='none')
    animator = d2l.Animator(xlabel='epoch', ylabel='loss',
                            xlim=[0, num_epochs], ylim=[0.22, 0.35])
    n, timer = 0, d2l.Timer()
    for _ in range(num_epochs):
        for X, y in data_iter:
            optimizer.zero_grad()
            out = net(X)
            y = y.reshape(out.shape)
            l = loss(out, y)
            l.mean().backward()
            optimizer.step()
            n += X.shape[0]
            if n % 200 == 0:
                timer.stop()
                # `MSELoss` computes squared error without the 1/2 factor
                animator.add(n/X.shape[0]/len(data_iter),
                             (d2l.evaluate_loss(net, data_iter, loss) / 2,))
                timer.start()
    print(f'loss: {animator.Y[0][-1]:.3f}, {timer.sum()/num_epochs:.3f} sec/epoch')

#@save
def train_concise_ch11(trainer_fn, hyperparams, data_iter, num_epochs=2):
    # Initialization
    net = tf.keras.Sequential()
    net.add(tf.keras.layers.Dense(1,
            kernel_initializer=tf.random_normal_initializer(stddev=0.01)))
    optimizer = trainer_fn(**hyperparams)
    loss = tf.keras.losses.MeanSquaredError()
    animator = d2l.Animator(xlabel='epoch', ylabel='loss',
                            xlim=[0, num_epochs], ylim=[0.22, 0.35])
    n, timer = 0, d2l.Timer()
    for _ in range(num_epochs):
        for X, y in data_iter:
            with tf.GradientTape() as g:
                out = net(X)
                l = loss(y, out)
                params = net.trainable_variables
                grads = g.gradient(l, params)
            optimizer.apply_gradients(zip(grads, params))
            n += X.shape[0]
            if n % 200 == 0:
                timer.stop()
                p = n/X.shape[0]
                q = p/tf.data.experimental.cardinality(data_iter).numpy()
                # `MeanSquaredError` computes squared error without the 1/2
                # factor
                r = (d2l.evaluate_loss(net, data_iter, loss) / 2,)
                animator.add(q, r)
                timer.start()
    print(f'loss: {animator.Y[0][-1]:.3f}, {timer.sum()/num_epochs:.3f} sec/epoch')

12.5.6. 小结¶

  • 向量化使代码更高效，这既是因为深度学习框架的开销降低了，也是因为 CPU 和 GPU 上的内存局部性和缓存更好。

  • 随机梯度下降带来的统计效率与一次处理大批量数据带来的计算效率之间存在权衡。

  • 小批量随机梯度下降兼具两者的优点：计算效率和统计效率。

  • 在小批量随机梯度下降中，我们处理通过对训练数据随机置换而得到的批量数据（即每个观测每轮只处理一次，尽管顺序是随机的）。

  • 建议在训练过程中衰减学习率。

  • 一般来说，以实际时钟时间衡量，小批量随机梯度下降在收敛到较小风险方面比随机梯度下降和梯度下降更快。
